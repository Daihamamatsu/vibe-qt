# 古典タートルズの最終日決済表示バグ調査・修正記録

## 1. 概要

3132.T の 2026年9月28日が S1 決済として表示される事象を調査した。
調査の結果、古典タートルズのバックテストがデータ末尾まで残った未決済ポジションを、最終日の終値で `end_of_data` 決済として記録していたことが原因だった。

この処理は銘柄ごとのデータ異常ではなく、すべての銘柄に共通するフロントエンドのバックテストロジックに存在していた。

## 2. 発生原因

対象ファイル:

```text
stock-app/frontend/src/utils/classicTurtle.ts
```

修正前は、バックテスト終了時にポジションが残っていると、次の処理を実行していた。

```ts
const finalExit: ClassicTurtleExit = {
  date: bars[lastIndex].date,
  price: lastClose,
  reason: 'end_of_data',
};
trade.exit = finalExit;
day.exit = finalExit;
day.position = null;
```

このため、実際に以下の条件へ到達していない場合でも、最終日が決済日になっていた。

- 2N ストップ
- System 1 の決済チャネル
- System 2 の決済チャネル

3132.T のローカル DB には、2026年9月28日の OHLC データが存在していたため、日付欠損が直接原因ではなかった。

## 3. 影響範囲

`end_of_data` は通常の `stop` / `channel` 決済と同じ `exit !== null` として扱われていた。
その結果、次の表示・集計へ影響していた。

- 最新日に S1/S2 決済マーカーが表示される
- 未決済ポジションが「保有: なし」になる
- 完了取引数へ未決済ポジションが含まれる
- 評価損益が実現損益として扱われる
- SQN の対象へ未決済ポジションが含まれる

## 4. 類似箇所の確認結果

### 4.1 同じ原因の波及

古典タートルズでは、以下の処理が `trade.exit !== null` を基準としていた。

- `Stock.vue` の完了取引数・総損益・SQN 集計
- 古典決済チャートマーカー
- 古典取引履歴の決済日表示

根本原因で `trade.exit` を生成しないようにすることで、これらの波及も同時に解消した。

### 4.2 旧タートルズ計画

`computeTurtlePlan()` は最終日まで EXIT 条件が成立しない場合、`exit.date` を `null` のまま返す。
そのため、同じ最終日強制決済の実装は確認されなかった。

### 4.3 日付順序

バックエンド API は日付降順でデータを返すが、画面の DB 読み込み処理では日付昇順へ変換している。
一方、バックテスト関数単体は入力配列の順序を前提としていたため、呼び出し元に依存しないよう、バックテスト内部でも日付昇順へ正規化する処理を追加した。

## 5. 修正内容

### 5.1 未決済ポジションを最終日に強制決済しない

バックテスト末尾の `end_of_data` 生成処理を削除した。

最終日まで未決済の場合は、次の状態を維持する。

- `trade.exit === null`
- 最終日の `day.exit === null`
- 最終日の `day.position !== null`
- 最終日の終値で計算した評価損益と R 倍率

これにより、未決済取引は完了取引数・総損益・SQN・決済マーカーへ混入しない。

### 5.2 入力バーを日付昇順へ正規化

`backtestClassicTurtle()` の内部で入力配列をコピーして日付昇順に並べ替える。
呼び出し元が日付降順の API データを直接渡した場合でも、時系列計算が逆転しないようにした。

## 6. 追加した回帰テスト

`stock-app/frontend/src/utils/classicTurtle.test.ts` に次のテストを追加した。

1. 最終日まで保有したポジションが強制決済されず、評価損益と保有状態を維持する
2. 日付降順の入力でも、日付昇順の入力と同じ結果になる

## 7. 検証

以下のコマンドで検証する。

```bash
cd stock-app/frontend
npm test
npm run typecheck
npm run build
```

バックテストは外部 API や実市場データへ依存せず、固定 OHLC データによる Vitest で検証する。
